# v0.2.0-alpha.1：Google Docs foundation

## 目標與邊界

第一批提供 Google Docs 優先、DOCX 並存的 prompt-only Skill 工作流程：實際能力／權限辨識、優先局部編輯既有文件、無文件時建立、逐項寫入已確認內容、版本條件保護人工修改、寫後讀回，以及操作失敗時停止、保留現況與清楚回報；DOCX 僅在使用者明確選擇時啟動完整獨立流程，不自動回退或擅建替代文件。三份核心 Skill 內嵌相同最低規範，法律規則共用，不新增第四個 Skill。

不包含獨立編輯後端、OAuth／API Key 管理、完整複雜三欄排版、跨模型真人驗收、自動雙向同步、Alpha Tag 或 Release。v0.1.x 正式發布檔案與發布工作流不變；Google Docs 尚未穩定前，v0.2 使用 Alpha／Beta／RC，不直接 Stable。

## PR #31 審查調整

文件模式已依使用者新確認需求修正：Google Docs 建立、讀取、寫入失敗、缺少權限或版本衝突無法安全解決時，停止相關操作並保留現況，回報原因、已完成部分及不確定結果。不得自動改用 DOCX、建立替代 Google Docs 或覆蓋其他文件。DOCX 完整保留，只在使用者明確選擇時啟動。法律來源、政策確認與原文保真等既有法律規則不變。

## 可重現驗證

在 repository 根目錄執行，僅需 Bash、Git 與 Python 3 標準庫：

```bash
python3 scripts/validate.py
python3 -m unittest discover -s tests -v
git diff --check
```

PR #31 的 base 已為 `develop-0.2`。CI 對 main、develop、develop-0.2 的 push 與以這些分支為 base 的 PR 執行既有 read-only 驗證，不硬編碼單一 feature 分支；feature 後續提交由既有 PR 的 synchronize 事件驗證。

本批執行結果：封裝驗證 PASS（五檔內容、來源位元組、CRC、解壓縮與兩次獨立封裝 SHA-256 一致）；119 項測試通過，包含既有 116 項與 3 項靜態契約／CI 分支設定／ZIP 自足性檢查。這些不是模型服從性測試，也不驗證 API 或真實協作行為。測試輸出的虛構 Beta tags 僅存在暫存 Git fixtures，不是專案 Tag／Release。

`GOOGLE DOCS LIVE OPERATIONS: NOT TESTED`：本環境沒有可呼叫的 Google Docs 建立、讀取及編輯工具，未建立任何測試文件。建立、權限、條件寫入、人工衝突、讀回、Google Docs 轉 DOCX 均未實測；沒有以模擬資料宣稱整合成功。DOCX 既有 OOXML 參考測試通過；本批真人模型、Google Docs／Word 渲染、字型與視覺 QA 皆 NOT TESTED。

後續在支援平台依 [工作流程與人工驗收](../google-docs-workflow.md)使用授權的虛構文件驗證，留下實際工具／revision／讀回證據，再評估 Beta／RC。第一批不啟用任何新發布工作流；既有 Beta workflow 仍只驗證 develop 歷史，不能直接拿來發布 v0.2。
