- 目前 repo 的主功能是 Agent Skills；既有可執行程式為發布封裝與 Feedback Package，沒有正式 DOCX engine。
- 歷史 DOCX runner 留在 ignored test-output，未隨 checkout 提供。本批不把歷史 5/5、17/17、31/31 改稱重跑。
- 已有規則包含中文條號、條號＋第一項同 paragraph、唯一 U+3000、單行距、段距 0、項款目、原文保真、黑色格線、East Asian font 與變動文字底線。
- v0.1.3 記錄長表格分頁 PARTIAL、未變動「日前」曾誤加底線、部分中文字右界未完全整齊、字型／原始 DOCX 獨立複核缺口；根因並未全面確認。

本批增補 repeated header、長列可分割、避免 exact row height／整表 keepNext/keepLines/cantSplit，
穩定三欄／來源對應與明確 generation/structure/fidelity/render/visual/font QA 分層。
Issue #5 決策及來源、Issue #9 Feedback Package、START-HERE/gate、正式 ZIP 五成員均保留。

## 可重建的虛構案例

canonical fixture：[cases.json](../../tests/fixtures/docx/cases.json)。
所有文字是虛構《文件測試辦法》、版本 docx-fixture-1，不是現行有效法律、真實使用者決策或正式提案。
`repeat` 明確定義壓力測試正文的重複次數，並不是渲染重複的許可；項／目編號只出現一次，續文才重複。
三欄文字均從 row ID（R01–R08）對應的同一 fixture 建立；修正僅「七」→「五」及 C05 的明定新增段落。
C03 的「应」是故意保留的來源字形；不能為排版而「校正」成別字。

| Case | 情境 | 結構與保真判準 | 本機 PDF 頁數 |
| --- | --- | --- | --- |
| C01 | 短條文一般修正 | 僅五／七加底線，日前、條號、空白不加 | 1 |
| C02 | 單條長文大於一頁 | 允許同一邏輯列分頁，正文完整，不用 fixed height 截斷 | 8 |
| C03 | 三條長文連續 | 逐條三欄對應，不混入前後列，來源字形不改 | 9 |
| C04 | 條、項、款、目 | 分別獨立 paragraph，原生 indent、不插入假縮排空白 | 1 |
| C05 | 新舊欄長度差距大 | 舊文短、新段落很長；新字底線排除空白，續頁空欄不塞別條 | 6 |
| C06 | 中文標點、括號、長說明 | 全形標點保留；說明欄可跨頁，其他兩欄不重複正文 | 8 |

Fixture 字型是本機實際可用的 **Noto Serif CJK TC fallback**，不是標楷體／全字庫正楷體。
12 pt、A4 portrait、各欄 3600/3600/2886 twips、邊距及縮排僅為可重建 QA 設定，不是新法規範本。
條第一項 left=C/hanging=C；第二項 left=C/firstLine=C；款 left=2C/hanging=C、目 left=3C/hanging=C。
款目數值是本測試採用的可辨識階層，正式機關範本仍優先，不一律強制所有文件用相同點數。

## 執行方式

核心 fixture writer/validator 使用 Python 標準庫（zipfile/ElementTree/difflib）；CI 無新增依賴：

```bash
python3 scripts/validate.py
python3 -m unittest discover -s tests -v
python3 tests/docx_reference.py --output-dir test-output/docx-quality
```

生成 C01–C06 真正 .docx，原生 Word 表格與文字，並核對 ZIP/XML、精確列／欄／段落全文、
欄寬、字型屬性、黑色格線、段落／縮排、split/header/height/keep、diff 底線。
這是 **direct-format reference contract**，不是通用 OOXML schema、styles 繼承、法律語義或版面 validator。
產生器與 validator 共享 fixture expansion/diff 計算；另外對短案五／七底線及舊文實際字串做獨立斷言，
並以真正被竄改的 DOCX 正反例確認檢查能失敗。不把互相一致的 helper 當成全面正確性證明。

負例涵蓋：改寫／截斷／重複／交換欄位、取消標題重複、禁止 split、exact height、
keepNext/keepLines/pageBreakBefore、錯誤縮排、缺 East Asian font、1.5 行距、灰色框線及誤加底線。
首次「改字」負例選中了未含七字的 run，沒有造成變更；本批已修正 mutation 指向實際七字 run，
確認反例確實被拒絕。沒有透過放寬 validator 讓測試通過。

## 可選本機渲染與視覺檢查

Microsoft Word 或其他支援 DOCX 的 renderer 需另外實際執行；CI 不假設已安裝這些工具。
本機已使用 LibreOfficeDev 26.8.0.0.alpha0（build 2c87e51eeaa2b413ff4ae097b2705eea1995d8e5）：

```bash
soffice -env:UserInstallation=file:///tmp/sa-lo-docx-quality --headless \
  --convert-to pdf --outdir test-output/docx-quality test-output/docx-quality/C*.docx
# 以下 optional probe 需要本機已可用的 PyMuPDF / Pillow，不是標準庫 CI 的必要依賴。
python3 tests/docx_pdf_probe.py test-output/docx-quality
```

只檢查本次真的生成的文件；確認六份 PDF 均存在且新生成，不把舊 PDF 冒充當次結果。
probe 逐頁按三欄位置提取文字，合併跨頁內容與 fixture 比較（忽略排版 whitespace）；
DOCX 層仍逐字精確核對原文／空白。probe 記 DOCX/PDF SHA-256、頁數、embedded fonts、
每頁同一標題帶的三欄名稱、文字 bbox 是否在頁邊距內，並產生 contact sheets。
C06 說明正文也含「說明」；不能把所有 search 命中誤當多個 header。已改按 y 位置核對標題列。
probe 不檢查所有視覺細節，不會自行寫 VISUAL PASS。

人工／Agent 視覺核對要真的看圖：每頁總覽檢查空白頁／過大空白、重複標題、欄對應、表格溢出；
另放大段落階層、條號＋首項、底線與頁／列邊界。判斷空白欄時要區分合法的長短差異，
不為了補滿而重複或刪除正文。逐字稿式文字比較、bbox 或 OOXML PASS 都不能取代看圖。

| 真人模型／法律正確性 | NOT TESTED / UNVERIFIED | 無模型對話／真實案件輸出驗收 |

看圖未發現本 fixture 的強制不分割空白頁、可見欄位錯置或文字裁切；
C05/C06 續頁有合理空白欄，因兩側文字長度不同，不把它判成截斷。
C01 close-up 底線只在五／七；C04 條／項／款／目仍可辨識；C03 相鄰列三欄同時交接。
以上只限目前 renderer／fallback／六個受控案例，不能說所有正式 DOCX 已修好。

若其他環境無法渲染或未實際看圖，須寫 **VISUAL QA: NOT TESTED**。
剩餘風險：Word／跨平台字型與分頁差異、style 繼承、正式範本、真實長文件／表格合併儲存格、
每字視覺校對、歷史使用者 DOCX 與真人模型遵守都未驗。保留歷史限制，不改寫舊結果。

產物（DOCX/PDF/PNG/probe JSON）留在 ignored test-output/docx-quality，不加入 Git 或正式 Release ZIP。
可在 Feedback Package outputs.verification／limitations 記錄本表及實際檔案身分／來源，
不得將靜態 CI 結果混成 visual／真人模型 PASS。本批不 merge、不建 Tag、不發布 Release。
