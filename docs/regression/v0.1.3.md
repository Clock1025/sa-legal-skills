# v0.1.3 Regression Record

v0.1.3 以 v0.1.2 為基準，目標是針對真實案件與跨平台使用中已實際出現的缺陷做穩定化修正。此紀錄應隨修改與測試同步更新，不在發布前才依記憶重建。

## 本版已確認修正

### 多法規正式提案分案

真實大型修法測試發現，模型可能因政策目的相同，把多部不同法規放進同一份正式提案。

v0.1.3 規則：
- 一部法規／規章原則上對應一份獨立正式提案。
- 多部法規需要連動修正、制定或廢止時，各案仍須各自具有完整的案由、總說明、對照表或其他正式材料。
- 執行環境支援檔案輸出時，預設分別輸出不同檔案。
- 若分檔會顯著增加產生成本、token 使用量或操作負擔，可詢問使用者是否接受彙整工作檔；不得僅為節省 token 自行合併。
- 即使同一工作檔內收錄多案，也不得把不同法規合成單一案由或單一正式提案。
- 若適用程序或正式範本明確允許多法規 omnibus 提案，從其規定並說明依據。

### 跨法規移列之現行條文欄

真實全文修正案發現，將其他法規條文併入目標法規時，模型可能把來源法規的原條次與原文直接填入目標法規對照表的「現行條文」欄。

v0.1.3 規則：
- 「現行條文」只比較目標法規本身的現行版本。
- 若移入的條文在目標法規現行版本不存在，應視為整條新增；現行條文欄填「（本條新增）」。
- 來源法規名稱、原條次與移列關係應放在說明欄或工作版來源追蹤紀錄。
- 來源法規文字可另行保留供追蹤，但不得冒充為目標法規的現行條文。

### Skill transition pre-Skill gate

Claude Sonnet 5.5 Medium 的真實案件測試中，regulation-review 階段正常；但切換至 amendment-drafting 時，模型明確承認未能讀取新 Skill，卻仍在同一回覆先產生暫擬修正條文。

v0.1.3 強化 canonical prompt：
- 工作中切換 Skill 時，新階段開始前仍必須完整讀取新 Skill。
- 已讀取前一個 Skill、已取得案件材料、已完成前階段分析，都不能取代新 Skill 的讀取。
- 新 Skill 無法讀取時，只能協助取得／貼上／上傳該 Skill；不得先產生屬於新階段的暫擬內容。
