# 在 ChatGPT 使用

不必安裝 Skills。下面是提供指引和案件文件的操作方式；按鈕名稱、檔案支援及工具能力會隨帳號、模型和介面版本改變。

## 已知問題與限制（依既有實測）

### 歷史 v0.1.3：GPT-5.6 Sol／High

- **切換 Skill 時曾提前起草（2026-10-04）：**R03 全新對話重測中，模型承認未讀取新的 `amendment-drafting`，仍依「先做、不用等」要求產生暫擬條文與提案材料，判定 FAIL。遇到這種情況，停止該階段起草，先完整提供並讀取對應 `SKILL.md`；不要沿用未讀時產生的草稿當正式定稿。
- **DOCX 曾多畫底線：**當次文件把「五日前／七日前」整段加底線，正確應只標變更字「五／七」。核對實際 Word 檔的文字與底線；多畫未修改文字是格式問題，不能直接當成原文被改寫。
- **完整讀取的證據可能不足：**不能只依模型自述認定已讀完整 Skill。無法核對的讀取動作列為限制，不等於已可觀察的文件內容都失效。

以上是特定模型與條件的歷史觀察，不代表所有 ChatGPT 模型都有相同問題。詳見 [v0.1.3 回歸](../regression/v0.1.3.md)。

### v0.1.4-beta.1：GPT-6 首輪觀察（2026-10-12）

依[正式 Beta Release Notes](https://github.com/Clock1025/sa-legal-skills/releases/tag/v0.1.4-beta.1)，P0-CASE-03 與 P0-CASE-08 為 PASS、P0-CASE-04 為 PARTIAL、P0-CASE-05 為初判 FAIL。
這是維護者回報的初步行為觀察，**不是正式 Beta 驗收結論，也不是 GPT-6 整體通過率或可靠度排名**。
要試用 Beta，請從該 Release ZIP 取得 Skill，或指定該版固定 Commit；不要把 `main` 的檔案當成固定 Beta 的版本證據。

- CASE-04：含糊的「加上去」可能沒有先確認指涉。請明確指出同意哪個方案、適用範圍及仍未決事項，檢查正式稿有沒有多採納政策。
- CASE-05：不完整條文尚未釐清前，可能提前產生占位內容。請補明原意後再起草；不要把模型自行補出的占位文字當成已確認條文。

### 兩份實際模型 DOCX（2026-10-13）

依 PR #19 的匿名化檢查摘要：

- [第一份虛構案例](https://github.com/Clock1025/sa-legal-skills/pull/19#issuecomment-6140830914)：原文內容符合提供基準，但未修改的「日、前」多畫底線，屬 LOW 格式風險。模型自述讀取 `main`，不能算固定 Beta Skill 的有效正式回歸通過。
- [第二份較長、多項款及兩列修正案例](https://github.com/Clock1025/sa-legal-skills/pull/19#issuecomment-6141051567)：獨立離線比對的原文、段落、原生表格與底線符合基準，沒有內容或底線警示；另經 LibreOffice 渲染並人工看頁，未見截斷、錯欄或溢出。Microsoft Word 跨平台表現未驗證，不同預覽環境也曾呈現不同頁數。

第二份模型自述讀取固定 Beta Skill，但實際完整讀取及生成鏈仍未獨立證實；精確模型版本／設定也有證據限制。兩份修正說明都未做逐字基準比對。
這些是**文件檢查結果，不代表 GPT-6 全面遵守 Skill**。取得文件後仍要核對來源、修正決定、說明、底線與自己使用的 Word 版面；詳細證據留在 PR #19，不和歷史測試、首輪 P0 觀察或 CI 混算。

跨平台的精簡總覽見[模型與平台使用建議](model-compatibility.md)。

## 開始對話並提供 Skill

1. 開啟 [ChatGPT](https://chatgpt.com)，登入後選擇「新對話／New chat」（或目前介面的新增對話按鈕）。
2. 在平常輸入訊息的文字框貼入[START-HERE 的唯一可複製提示詞](../../START-HERE.md#可複製提示詞)。只說明你想解決的問題即可，AI 可協助判斷本次 Skill。
3. 若已知要用哪份 Skill，直接送出以下文字，並依需求替換路徑：

   ```text
   請實際讀取 https://github.com/Clock1025/sa-legal-skills 的
   skills/regulation-review/SKILL.md，再依其中規則處理案件。
   若不能讀取，請明確告知，讓我提供檔案；不要宣稱已讀取。
   ```

以下為使用者回報的 **2026-10-02** 實測紀錄：在 **ChatGPT 對話環境**中，GitHub zero-install 成功，指定 `regulation-review` 的描述性分析與合規分析實測成功；**模型版本未記錄**。詳見[v0.1.1 紀錄](../regression/v0.1.1.md)。這是當次人工實測回報，不是本輪自動化測試；本輪未重新執行。平台、模型與工具能力可能更新，不代表所有 ChatGPT 對話都能讀 GitHub。

## 讀不到 GitHub 或要提供文件時

從[三份 Skill 清單](generic-agent.md#取得本次需要的-skill)開啟本次需要的檔案，完整複製並貼入文字框；或下載 `SKILL.md`，用目前介面提供的附件／新增檔案功能上傳。只需本次使用的 Skill。若檔案格式被拒絕，改貼全文，不必安裝。

再以附件提供正式 PDF／DOCX，或把法規全文貼入訊息，並說明法規名稱、版本／生效資訊、案件事實與問題。先要求 AI 回報讀取限制；「已讀取」的文字回覆不代表 PDF 每頁都已核對。

## 要正式 Word 文件時

制度方向確認後，要求「請依 `amendment-drafting` 產生可編輯 DOCX，保留原生 Word 表格、底線、中文字型與法規段落縮排；如有正式範本，請沿用」。需要切換 Skill 時，讓 AI 實際讀取或提供對應檔案。若目前環境不能建立 DOCX，要求明確告知並提供完整結構化內容，不把純文字回覆視為已產生 Word 檔案。

官方操作參考：[ChatGPT 網頁版使用說明](https://learn.chatgpt.com/docs/web)。以目前帳號可見功能為準。
