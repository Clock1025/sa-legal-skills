# alpha.2 母版人工驗收案例

來源：[Issue #32](https://github.com/Clock1025/sa-legal-skills/issues/32)。以下是授權平台可操作的**虛構測試輸入及預期結果**，不是實際 API 執行證據、有效法規或使用者案件政策。此批在 Codex 僅作靜態契約檢查；六組 Google Docs 情境全部 **NOT TESTED**。Issue 記錄的母版原型視覺驗收／ChatGPT 工具底線測試不能搬成這批自動化 PASS。

## 準備及證據

在可用平台先完整讀取測試 commit 的 `amendment-drafting/SKILL.md`；由使用者當次指定並授權複製母版、編輯虛構副本及進行過期 revision 拒絕測試。不要把私人母版／副本 URL、ID 或案件內容提交到公開 repo。每案證據存於使用者授權的私人案件紀錄：

- 平台／工具／模型、Skill commit、執行日期、母版授權與副本身分核對、實際 tab、讀取範圍、前後 revision。
- 每批預期文字／樣式、實際請求與回應狀態、讀回文字／結構／有效 underline runs、未完成及不確定結果；不存密鑰。
- 格式屬性：A4 直式、指定 `DFKai-SB`、24／14／20／12 pt、原生換頁、三欄各 139.5 pt；不能讀回者列 UNVERIFIED。
- 真實視覺證據：實際副本或其渲染的每頁檢查、裝置／renderer、頁數與檢查範圍、使用者驗收回覆。API 字型名稱讀回不是字型實際顯示證據。

原母版保持唯讀；所有寫入限定已核對副本，不更動分享權限。每條文字、擴列或樣式修改均先讀取、用新 revision 原子條件寫入、再讀回。結果不明先核對再決定是否續寫；不能解決就停下，保留人工修改，不建立替代 Google Docs 或 DOCX。

## 六組必要情境

### G01：複製、短替換與精確底線

測試來源：虛構《母版驗收辦法》第一條，現行「第一條　應於會議七日前公告。」；本案例明定已確認修正為「第一條　應於會議五日前公告。」。測試理由是「測試將公告期限由七日調整為五日」，不是對真實政策的建議。提案人用明示虛構的測試身分，不沿用母版舊案姓名。

授權後複製並讀回不同 document ID、實際 tab／revision；原生填入一列。現行欄只畫「七」，修正欄只畫「五」；「日前」、條號、U+3000 及說明欄均不畫差異底線。若初次讀回「日前」被畫到底線，記錄首次 FAIL／缺陷，僅在新版本條件下校正受影響格式，再讀回記錄修正結果，不能把首次結果寫成直接 PASS。

### G02：增字、人工修改與純改號

接續同一副本，把已確認的測試新文從「應公告會議地點。」改為「應公告會議日期、地點。」。僅「日期、」是新增底線。先由人工在無關的提案說明段落加入「人工保留註記」，再讓 AI 重讀及局部處理本條；註記必須原樣保留，不能改寫整份文件。

另以「第二條　應公告會議地點。」→「第三條　應公告會議地點。」測純改號，不把全文畫底線；在說明記錄編號調整，若有連動引用變動另列。未實測的真實多人同時競爭不得用這個依序操作冒充通過。

### G03：至少三條原生擴列、整條新增／刪除

使用獨立授權的測試副本，三個邏輯資料列依序填入下表；G01 的替換列加上新增與刪除列，必須超過母版初始兩列。這裡 Markdown 表格只是案例規格，實際文件必須是原生可編輯表格。

| 修正條文 | 現行條文 | 說明 |
| --- | --- | --- |
| 第一條　應於會議五日前公告。 | 第一條　應於會議七日前公告。 | 測試將七日調整為五日。 |
| 第四條　應公告會議日期。 | （本條新增） | 虛構新增公告日期義務，僅供驗收。 |
| （刪除） | 第五條　應保存紙本副本。 | 虛構刪除紙本保存義務，僅供驗收。 |

先讀回擴列，再計算儲存格範圍，逐條條件寫入與讀回。新增欄文字、刪除欄舊文字除結構性空白外畫真正底線，兩個括號標記均不畫；未變動字及說明不畫。確認三個資料列、條次、三欄內容／順序與理由一一對應，沒有母版樣本／佔位殘留；所有新增列維持 12 pt、DFKai-SB 與三欄等寬。

### G04：長文、項款目、真實分頁及中斷續寫

重用既有虛構 [DOCX 來源 fixtures](../../tests/fixtures/docx/cases.json) 的 C02 長段落與 C04 項款目結構作文本輸入，**不沿用其 DOCX 字型／渲染證據**。製作一個含 C04 層級及 C02 的長文第二項的虛構條文：repeat 按 fixture 展開為原段落內重複字句；各項／款／目仍各為獨立段落。新舊側的 `{days}` 分別替換成五／七，其他內容逐字相同；只畫這一字差異。保留展開後的完整來源快照供讀回逐段比對。

在具備原生工具的平台實際填入，確認長列跨頁不截斷、重複或錯欄，段落層級不合併，標題與表頭仍可辨識。以實際頁面檢查分頁／裁切／續頁；工具不支援的分頁設定明列限制，不宣稱等同 Word。完成一批並讀回後中斷，依 checkpoint 重讀同一副本再續寫下一條，確認沒有重複複製、重複列或內容。未確認前批結果時不得直接重送。

### G05：過期 revision 必須拒絕

僅在使用者明確授權的虛構副本：先讀 revision R1，讓人工加入可識別註記使版本改變，再以 R1 的 `writeControl.requiredRevisionId`（或平台文件明訂的原子等效機制）嘗試同一目標的局部修改。這是特別授權的負例驗收，不是正常工作流程刻意用過期版本。保存實際 API 拒絕回應並讀回確認人工內容完整；使用 `targetRevisionId` 自動合併不能算通過。

拒絕後停止舊 request，不強制覆寫／重試／自動 DOCX／建替代副本；報告未完成部分，僅在重讀與必要釐清後重新規劃。沒有工具暴露原子條件時應停止並記錄 UNSUPPORTED，不能用模擬回應或先讀後寫冒充本案例 PASS。

### G06：完整副本視覺與字型驗收

對實際產物逐頁檢查第一頁標題 24 pt、提案欄 14 pt、另起頁的對照表標題 20 pt、表頭／內文 12 pt、三欄等寬、長文接續、項款目、真正底線與指定標楷體的顯示。保留 API 讀回結果與人工視覺回覆，分開判定。API 只能驗證值，不能證明沒有字型替代；Android／iPad 未查看就寫 NOT TESTED，即使桌面顯示正常也不能外推。

## 結果記錄

每組分開填：操作／文字與樣式讀回／渲染／使用者視覺驗收／裝置字型 QA，以及 PASS、FAIL、PARTIAL、UNSUPPORTED 或 NOT TESTED 與證據。修正後重測須保留首次缺陷與新結果。未執行六組案例時，維持 `GOOGLE DOCS LIVE OPERATIONS: NOT TESTED` 及 `VISUAL QA: NOT TESTED`；本地 unittest 通過只證明 prompt／ZIP 契約，不能替代以上驗收。
