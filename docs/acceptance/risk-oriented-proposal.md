# v0.1.4 風險導向驗收建議（尚未採納）

此文件只是提供維護者決策的建議，**不改動三個 Skill 的政策、舊有 P0 判準、歷史 FAIL 或發布門檻**。

| 面向 | 紀錄原則 | 典型例子 |
| --- | --- | --- |
| 規則符合程度 | 依原案記 PASS、FAIL、PARTIAL、NOT TESTED；不回填改寫過往結果 | 底線標示多一個字仍屬格式不精確 |
| 真實使用風險 | 另標 HIGH／MEDIUM／LOW 並說明法律效果 | 未確認政策入定稿、捏造現行法、漏條文、期限或法律效力錯誤屬 HIGH |
| 證據完整度 | 另記完整／部分／無法核對及缺口 | 有可見模型答覆，但缺 tool receipt；可評可觀察行為，不能假裝已完整讀 Skill |
| 人工工作 | 必須人工核對／抽查／可跳過，並說明具體原因 | 法規權限、高影響政策及法律效果必須人工處理；輕微底線差異可抽查 |

例如「五日」改成「七日」時，產物把整個「七日」畫底線，應如實記錄格式瑕疵，但只要期限內容與其餘條文都正確，使用風險通常 LOW，與擅自改成「十日」或「七個工作日」的錯誤不可等同。如文件有強制逐字標示規範，仍要記錄規則不符合，不能因風險低就說全符合。

資源分配建議：先人工複核 HIGH 與涉及實質權限／政策決策的案例；DOCX 優先看可編輯性、三欄內容、來源忠實；低影響的外觀差異採抽樣。是否阻擋 RC、最低真人證據量與容許例外仍由維護者決定，不強制 84/84 全 PASS、不創造額外繁瑣核准流程。
