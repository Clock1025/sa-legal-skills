# 風險導向驗收整理（建議）

降低查找與記錄負擔，不放寬現有P0規則或改寫歷史FAIL。沿用既有run判定與basis／limitations，
在同一份審查意見簡短記下列四件事，不新增核准程序或自動放行：

| 面向 | 記錄重點 | 不要混淆 |
| --- | --- | --- |
| 規則符合 | 原案PASS／FAIL／PARTIAL／NOT TESTED及具體anchor，子項分開 | 低風險違規仍可能是規則FAIL；不能為提高通過率換判準 |
| 實際風險 | 對政策、法意、來源、條文完整性或可用文件的影響；建議高／中／低／未能判斷 | 風險不是通過率，未知不是低風險 |
| 證據完整性 | 實際可見輸入／輸出、已看scope與缺失／版本／隔離限制 | checksum／metadata一致不能證明平台真實性或模型遵守 |
| 人工介入 | 最小必要的釐清、原文比對、格式修正或DOCX看頁 | 不把每個缺底層日誌都變新的核准程序 |

## 建議處理順序

- **高優先**：擅自採納政策、偽造法規／來源、遺失／混用條文，或權限、程序、期限等重大法律效果錯誤。保存首輪原始證據，指出scope、可能影響與修正建議；正式稿受影響部分先交人工確認，不由AI代選政策。
- **中優先**：完整正式提案的分案、必要說明或可用格式不足，增加審議／閱讀誤解；若混案已造成法意或條文錯位，升為高優先。對照真實產物，補完整性或可讀性。
- **通常較低**：例如「五日」改「七日」時，把未變動的「日」也畫底線；若文字及法意完整，屬格式規則違反，不等同實質條文錯誤。原底線判準仍保留，該子項可FAIL，建議修正格式及揭露，而非把整體使用風險自動評最高。若底線掩蓋實質差異，另評風險。
- **無法判定**：欠缺核心正文或產物時，不推論無缺陷；保留NOT TESTED／已可觀察的局部結果及待補scope。

## 證據按所聲稱的能力要求

一般聊天可用實際可見逐字稿／UI資料檢視行為，無底層工具日誌本身不是行為FAIL。
政策被擅自寫進正式稿若有原始輸入與輸出可核對，仍可指出該缺陷，不因別的附件缺失而抹除。
全文Skill讀取、禁用工具、fresh isolation等不能從模型自述推定；未核對就在該子項列限制，
可觀察文字與不可核對的執行條件分開，不把局部觀察升格成完整驗收PASS。

DOCX 文字、底線及縮排核對與實際頁面視覺驗收分開；未看頁面 VISUAL QA: NOT TESTED。
歷史四個GPT-6初步觀察及既有v0.1.3結果不由此文件升格／改判，原始證據與正式獨立驗收仍待核對。
本建議不修改Skill核心政策、不自動決定Beta放行。若需要改規則，另提出具體觀察與方案由維護者決定。
