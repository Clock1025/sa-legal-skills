# 第一次使用：從想解決的問題開始

不會寫法規也可以開始。先用自己的話說明「現在遇到什麼問題」或「希望事情以後怎麼運作」，讓 AI 協助整理；制度選擇仍由你決定。

在你使用的 AI 開一個新對話，使用 START-HERE 中唯一的可複製提示詞開始，再用自己的話說明問題。介面操作可看 [ChatGPT](platforms/chatgpt.md)、[Claude](platforms/claude.md)、[Gemini](platforms/gemini.md)或[其他 Agent](platforms/generic-agent.md)。

## Google Docs 首次試用操作卡

這是 v0.2.0-alpha.2 封閉試用指引，不是 Stable；是否已發布以 [Alpha.2 發布頁](https://github.com/Clock1025/sa-legal-skills/releases/tag/v0.2.0-alpha.2)為準，本頁本身不代表已發布。請先從 [START-HERE 的封閉 Alpha 入口](../START-HERE.md#封閉-alpha-試用先從這裡開始)取得固定版本 Skill；不要使用 main 或舊版 Release。你只要依序操作，不必選分支、安裝程式或看 CI。以下是操作步驟，不是另一份完整啟動提示詞。

1. **先選對 Skill 並讀完。** 開新對話，使用 START-HERE 唯一提示詞；這次要試做修法文件，選固定版本的 `amendment-drafting`。先請 AI 完整讀取，讀不到就貼入或上傳完整檔案；它未讀完前，不提供案件材料，也不開始起草。若方向未定，先依 START-HERE 選適合的 Skill 整理，切換階段時再完整讀取新 Skill。
2. **讀完後，再準備安全的案例。** 優先使用虛構案例或可公開的舊案；提供完整原文、來源、版本及想改的具體內容，舊案要標示為歷史測試材料。請 AI 列出已確認與未決事項，由你確認修改方向；不要把真實個資或未公開案件拿來測試，也不要讓 AI 猜原文或替你決定政策。
3. **提供有權使用的母版。** 把你有權使用、允許複製的 Google Docs 母版連結私下交給該對話，說清楚這次授權複製並編輯獨立測試副本。請 AI 先確認目前工具能否讀取、複製、局部編輯，以及防止覆蓋新修改；有連結不代表已取得權限。沒有母版可請試用聯絡人協助，不必把文件改成公開或提供密碼。
4. **確認副本，再逐條修改。** 請 AI 回報新副本的連結／名稱，確認與母版不同；只在副本操作，原母版不動。每確認一條就及時寫入，再讀回核對，不等整份重做。你可在副本手動修改，請 AI 每次動筆前重讀現況、保留你的變更；續作時使用同一副本，不重複複製或覆蓋全文。
5. **自己看內容與畫面。** 對照原文確認條號、項款目、修正文字與理由；確認只在真正增刪字畫底線，沒有漏字、重複、空白底線或殘留範例。查看說明段落首行縮排、法條階層、三欄等寬、長文跨頁及字型，不能只因 AI 說「完成」就當作驗收。哪些地方未確認，請分開列出。
6. **失敗就停下，保留現況。** 權限不足、缺少安全編輯工具、版本衝突無法解決或寫後讀回不符時，請 AI 說明原因、已完成部分及不確定結果，停止相關操作。不要強制覆寫、另建替代文件或自動轉 DOCX。若你另外明確選擇 DOCX，才使用它的獨立流程。
7. **只回報必要資訊。** 告訴試用聯絡人：平台／模型、Skill 固定版本 `c07803e`、操作到哪一步、預期與實際結果、AI 顯示的錯誤及能否重現；畫面截圖先遮掉私人內容。請勿在公開 Issue／PR 貼私人母版或副本連結／ID、未公開案件、完整私人對話、Token、Cookie 或其他憑證。需要查文件時另由聯絡人安排最小範圍授權，不把文件設為公開來排錯。

試用中遇到不支援或停止不代表你操作錯誤；請照實回報。真正跨對話恢復、長篇所有頁面及不同裝置字型仍是觀察項目。這次是收集問題的封閉 Alpha，產物須人工核對，不代表已正式提案或公布。

## 開始使用提示詞

請使用 START-HERE.md 中唯一的[可複製提示詞](../START-HERE.md#可複製提示詞)作為新手引導入口。該提示詞包含 repository URL、Skill 選擇優先序、讀取前門檻及提問方式；本頁補充使用流程與案件準備方式，不另維護一份完整提示詞。

判斷 Skill 時，以使用者目前要做的事為準：目前要檢查現行規定或制度，先用 `regulation-review`；已進入整體改革規劃、跨制度協調或大量待決事項追蹤，才用 `large-scale-reform`；方向已定並要準備正式修正文件，再用 `amendment-drafting`。

## 三種常見起點

下列是說明**想做什麼**的例子，不是第二份完整啟動提示詞。先依 [START-HERE](../START-HERE.md#可複製提示詞) 取得並完整讀取本次 Skill，再按它的要求提供正式法規原文、版本、案件事實與已確認的修正範圍。

| 一開始可以這樣說 | 通常會用到 |
| --- | --- |
| 「我想知道現行章程規定誰能公布議會通過的法律。」 | `regulation-review`：核對權限、程序與現行條文 |
| 「我想重新整理預算與請款流程，但很多制度選項還沒決定。」 | `large-scale-reform`：整理未決事項、跨制度連動 |
| 「制度方向已確認，我想製作修正條文對照表。」 | `amendment-drafting`：核對原文與修正決定後起草 |

不是每個案件都需要依序使用三份 Skill；工作階段真的切換時，再完整讀取新階段的 Skill。

## 接著提供什麼？

例如先說「我想弄清楚某人能不能代理會長」或「我已決定要增訂一個程序，但不知道怎麼寫」。AI 需要查規定時，再提供正式現行章程、法規或規章，以及版本／生效資訊和必要事實；引用到其他法規時，也盡量一併提供。可以上傳 PDF／DOCX 或貼入法規文字，實際解析能力依平台而定。

若不能讀 GitHub，打開需要的 `SKILL.md`，完整複製全文貼入，或上傳下載檔即可。不需要把三份 Skill 全部提供，也不必安裝或使用 Codespaces。完整讀取同一份 Skill 後，這些提供方式都能使用其中規則。

想要 Word 文件時，可說「制度方向確認後，請依 amendment-drafting 提供可編輯 DOCX；若環境不能產生檔案，請明確告知並提供完整文件內容」。不同模型的長文件處理、規則遵循與檔案輸出能力可能不同，取得結果後仍要核對法規來源與版面。
